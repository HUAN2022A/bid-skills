# bid-export：docx 终稿导出

把 markdown 章节合成一份排版规范的 docx 终稿。**这是排版阶段，不改内容**——内容已在 bid-draft 定稿、bid-check 自查，这里只负责把 md 正确映射成 Word 的标题层级、表格、目录、字体。

## 输入

当前目录（或用户指定）下的 `chapters/*.md`、`tender-analysis.yaml`（取格式要求）、`bid-outline.yaml`（取章节顺序与项目名）。

**前置检查**：建议先跑 `/bid-check` 确认无阻断性问题。若 chapters 里有大量 `[待补]`，提示用户确认是否仍要导出（导出稿会带着 `[待补]` 标记）。

## 格式规范

**默认排版不是写死的**——按优先级取格式：

1. **官方模板优先**：若 `tender-analysis.yaml` 的 `template_file` 非空（招标文件附了技术标模板 docx），**复刻模板格式**——用模板作为底稿，把章节内容填入模板对应的章节结构，保留模板的字体、字号、页眉页脚、封面、章节样式。这是最优先的，因为官方模板往往带性格式要求。
2. **招标文件格式要求**：从 `format_requirements` 提取明确规定的格式（字体、字号、份数、密封、目录、页码等），逐条遵守。
3. **通用标书排版**（无官方模板且无明确格式要求时的兜底，本项目类某央企电子招标平台电子标即属此类）：
   - 正文：宋体小四（12pt），首行缩进 2 字符，行距 1.3 倍；
   - 标题：一级黑体小二加粗，二级四号加粗，三级小四加粗；
   - 表格：Table Grid，表头加粗；
   - 目录：自动目录（TOC 域，设为打开文档时自动更新页码）；
   - 页码：页脚居中。

**官方模板的复刻做法**：把模板 docx 作为 `Document(template_path)` 打开（而非新建），在其章节占位处填入对应章节内容，或在模板基础上追加章节。这样能完整继承模板的样式表、页眉页脚、封面。若模板只有部分章节结构，按模板样式扩展其余章节。

## 流程

1. 读 `bid-outline.yaml` 确定章节顺序（按一级章 id 排序），读 `tender-analysis.yaml` 取项目名/格式要求/**模板路径**；
2. **判定格式来源**：`template_file` 非空 → 以模板 docx 为底稿复刻；否则新建文档用通用排版；
3. 按顺序读 `chapters/*.md`，解析 markdown：标题（# 层级）、表格（| 语法）、加粗、列表、**图片（`![图注](path)`）**；
4. 用 `export_docx.py` 生成 docx：封面（项目名+招标编号+投标人占位）→ 目录（TOC 域，打开自动更新）→ 各章正文；
5. 剥离章节头部的 `<!-- covers -->` 注释（不进入终稿）；
6. `[待补]` 标记保留并高亮（黄色底纹），提醒人工补充；
7. 输出 `{项目}/技术文件.docx`，向用户汇报：章节数、总字数、待补高亮数、格式来源（模板复刻/通用排版）。

## 关键实现要求

- **标题层级映射**：md 的 `#`→Word Heading 1、`##`→Heading 2、`###`→Heading 3，以此类推，确保自动目录能抓取；
- **图片嵌入**：`![图注](path)` 解析为嵌入图片——路径相对工作区解析，居中插入（宽度约 420pt 适配 A4 正文区），图注作为下一行居中加粗小五文字；图片文件缺失时输出 `[图片缺失：path]` 占位而非静默丢弃；
- **表格映射**：md 表格转 Word Table Grid，首行加粗；
- **章节顺序**：严格按 outline 的一级章顺序（1,2,2.1,...,10），不是文件名字典序——用 outline 的 id 排序；
- **covers 注释剥离**：HTML 注释不进入终稿；
- **CJK 字体**：正文和标题都要设中文字体（eastAsia），避免中文变默认西文字体。

## 边界

- 只排版不改内容（发现内容问题提示回 bid-draft）。
- 不含商务/价格卷（那是人工部分）。
- 导出的 docx 是技术文件终稿基础，盖章、签字、上传某央企电子招标平台制作工具等由人工完成。
