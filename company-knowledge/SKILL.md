# company-knowledge：公司素材入库

把散落的公司素材解析成**结构化、可检索的素材卡片**，是"公司事实只准引用素材库、不准编造"这条硬约束的落地点。素材库是跨标书复用的资产，一次入库、反复使用。

## 素材库位置

默认 `~/Documents/company-knowledge/`（敏感数据，独立于 skill 代码）。结构：

```
company-knowledge/
├── index.yaml              # 素材索引（所有卡片的目录与检索元数据）
├── cases/                  # 案例卡（历史项目/业绩）
│   ├── case-某电厂摘复正.yaml
│   └── ...
├── people/                 # 人员卡（简历/职称/资格）
│   ├── person-赵瑞星.yaml
│   └── ...
├── credentials/            # 资质与获奖（证书/荣誉）
│   └── credentials.yaml
├── ip/                     # 知识产权（专利/软著）
│   └── ip.yaml
├── capability/             # 研发能力（公司简介/团队/设施/研发投入）
│   └── capability.yaml
└── raw/                    # 原始文件归档（可选，移入或软链）
```

## 卡片 schema

### 案例卡（cases/case-*.yaml）—— 业绩与历史项目
```yaml
id: case-某电厂摘复正
type: case
name: 摘复正机器人及余煤清扫装置
client: 某发电集团下属电厂      # 终端使用单位
contractor: 大连华锐重工集团股份有限公司     # 合同签订单位（若我方是分包）
sign_date: 2025-09-25
amount_wan: null                # 合同金额（万元），资格判断关键，未知标 [待补]
scope: [摘钩, 正钩, 复钩]        # 覆盖的作业内容，资格判断关键
has_正钩: true                  # 资格要求常卡"含正钩"
is_同类摘复钩: true             # 是否翻车机摘复钩同类
proof: []                       # 证明材料：合同关键页/验收证明/用户证明 路径或状态
proof_status: 缺证明材料         # 齐全|缺证明材料|待核实
source: 某公司资信文件2026年.docx
tags: [翻车机, 摘复钩, 国能, 电厂]
notes: 与本项目技术路线一致
```

### 人员卡（people/person-*.yaml）—— 简历/职称/资格
```yaml
id: person-赵瑞星
type: person
name: 赵瑞星
field: 电力能源行业资深专家
title: 高级工程师               # 职称，资格判断关键（是否副高及以上）
degree: null                    # 学历
background: 20年中国电力行业自动化、智能化管理经验
project_experience: []          # 项目经历（项目负责人资格判断关键），未知标 [待补]
certs: []                       # 执业/职业资格证书
source: 资信文件
tags: [电力, 自动化, 高级工程师]
```

### 资质获奖（credentials/credentials.yaml）、知识产权（ip/ip.yaml）、研发能力（capability/capability.yaml）
按类型组织的清单，每条带 `name`/`issuer`/`date`/`source`/`tags`。

## 入库流程

### 1. 扫描原始文件

读用户给定的素材文件（docx/pdf），或扫描素材库目录里未入库的文件。

### 2. 解析提取

- **资信文件**：提取公司简介、资质证书、获奖荣誉、专利/软著明细、业绩表、人员构成、核心人员——这类文件信息密度高，是入库重点；
- **历史标书/技术文件**：提取项目案例（项目名、业主、技术路线、规模），作为案例卡；
- **简历/证书**：提取人员卡、资质卡。

docx 用 python-docx 提取（段落+表格），pdf 用 pypdf。业绩、专利、人员常在表格里，重点解析表格。

### 3. 生成/更新卡片

按 schema 写卡片 yaml。**关键原则**：
- **只记录原始文件里有的信息**，不推测、不补全；
- 资格判断关键字段（案例的 `amount_wan`/`scope`/`has_正钩`，人员的 `title`/`project_experience`）若原始文件没有，标 `[待补]`——这些是投标时要补的证明；
- 每张卡记 `source`（来源文件），保证可追溯；
- 已存在的卡片做增量更新，不重复建。

### 4. 更新索引

重建 `index.yaml`：所有卡片的 id/type/name/tags/关键资格字段的汇总，供 bid-draft 快速检索。

### 5. 汇报

输出入库摘要：新增/更新了多少案例卡、人员卡、资质、专利；**重点提示资格缺口**——哪些同类案例缺金额/缺证明材料、项目负责人候选人里谁缺职称/项目经历证明。

## 与 bid-draft 的衔接

bid-draft 起草时按 outline 的 `materials` 关键词在 `index.yaml` 检索，命中卡片后读卡片内容写入正文。卡片里标 `[待补]` 的字段，bid-draft 在正文对应处标 `[待补]`。

## 边界

- 只入库原始文件里有的信息，不编造、不推测。
- 资格关键字段（金额、职称、项目经历、证明材料）缺失时标 `[待补]` 并重点提示，不留空假装完整。
- 素材含敏感信息，素材库目录与 skill 代码分开，不随 skill 分发。
