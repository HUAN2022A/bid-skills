# bid-check：符合性自查

标书提交前的机器自查。核心逻辑：**评分点对照表是全流程的中枢契约**——bid-parse 提取评分点、bid-outline 挂到章节、bid-draft 逐章响应，bid-check 则回头核对"每个评分点/技术需求到底有没有被响应到位"。只检查、不修改，发现的问题列清单。

## 输入

当前目录（或用户指定）下的：`tender-analysis.yaml`、`bid-outline.yaml`、`chapters/*.md`。

## 三类检查

### 1. 评分点覆盖率矩阵

对每个 `category: 技术` 的评分项：
- 它在 outline 里挂了哪些章节？
- 那些章节的 `.md` 是否存在、是否有实质内容？
- 章节头部的 `covers` 注释是否声明覆盖了该评分点？

输出矩阵：评分项 → 章节 → 覆盖状态（已响应/章节缺失/未声明）。

### 2. 技术需求逐条响应核对

对每条 `tech_requirements`（尤其硬指标）：
- 在 chapters 里 grep 关键数字/关键词，判断是否被响应；
- 硬指标是否给出"招标要求|我方响应"的明确响应。

**关键词自动提取**（`extract_keywords()`，替代硬编码 kw_map）：从 `requirement_original` 原文按优先级提取——
1. 数字+单位（`97%`/`10秒`/`400N`/`120公斤`/`90天`/`24个月`/`IP65`/`RTX4060` 等）；
2. 品牌/型号（`ABB`/`SIEMENS`/`C70EH-A`/`ZC-YJV22` 等英文数字混合）；
3. 领域术语（`_extract_domain_terms()` 自动统计：引号词如"技术偏离表""差异表" + 高频词如"摘钩""翻车机"）；
4. 兜底取原文前 6 字。

换项目零配置，关键词从招标文件原文和大纲标题自动生成。

### 3. 废标风险 + 格式核对 + 缺口

- **废标风险**：对照 `disqualification` 清单，标注技术卷相关的风险点（如技术参数未实质响应、技术偏离表缺失、关键技术响应表缺失）；
- **格式核对**：章节是否齐全（对照 outline 叶章节）、章节编号是否与 outline 一致、技术卷是否混入报价信息（grep 价格/报价/万元等敏感词，命中则提示）；
- **[待补]缺口**：汇总所有章节的 `[待补]`，列出哪些内容缺素材/缺人工补充。

## 流程

1. 读三个输入文件；
2. 跑 `check_bid.py` 做机器可判定的检查（覆盖矩阵、关键词命中、待补扫描、章节齐全性）；
3. 模型补充**需要判断的检查**（响应是否"实质"、是否"优于招标要求"、措辞是否回扣评分标准）——这部分机器判不了，逐章读给结论；
4. 写 `{项目}/check-report.md`，含：评分点覆盖矩阵、技术需求响应表、废标风险清单、格式核对结果、[待补]缺口清单、**人工处理清单**（商务/价格/资质类，提醒人工完成）；
5. 向用户汇报：通过项、风险项、缺口项，以及建议回 bid-draft 补写的章节。

## --fix 模式（自动修复低风险项）

默认只检查不修改。用户明确要求自动修时跑：

```
python <本skill目录>/check_bid.py -d {项目} --fix
```

**只修纯机械、不碰语义的四项**（checker/fixer 配对，报告第七节输出修复记录）：

1. **covers 注释**：scoring 与 outline 不一致（子节继承父章挂点）时按 outline 重写；tech_reqs 是起草认领制（允许父章全集的子集），只清越界声明；
2. **文件名 id**：文件名前缀与 outline 章节 id 的明显笔误（数字序列相同仅点多寡不同）自动改名，无法唯一推断的留人工；
3. **图注编号**：`图 X-Y` 的 X 须等于章一级编号、Y 在章内跨文件连续，断号重号自动重编并同步正文"如图 X-Y 所示"引用；
4. **图片路径**：`![](figures/xxx.png)` 失效时在 figures/ 下找同名或唯一相似名修正，找不到留人工。

**红线**：--fix 只碰元数据和编号，绝不改正文语义；修复前自动备份 `chapters/` → `chapters.bak-<时间戳>/`，修复记录逐项可追溯。废标风险、待补清单、报价混入、覆盖缺口**永远只报不修**（要判断或补内容，交人工/回 bid-draft）。

## 输出 check-report.md 结构

```markdown
# 符合性自查报告
## 一、评分点覆盖率矩阵
## 二、技术需求逐条响应
## 三、废标风险清单
## 四、格式核对
## 五、[待补]缺口清单
## 六、人工处理清单（商务/价格/资质）
## 七、低风险项检查与自动修复（--fix 时含修复记录）
## 八、结论与建议
```

## 边界

- 默认只检查不修改；--fix 仅修四项低风险机械项（见上），且修复前自动备份。
- 商务/价格/资质类内容不在技术卷范围，但要在"人工处理清单"里提醒，防止静默遗忘。
- 机器能判定的（覆盖、关键词、待补、章节齐全、四项低风险）用脚本；需要判断的（响应质量、是否优于）用模型逐章读。
